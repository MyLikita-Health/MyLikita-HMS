ISSUE RESOLVED: Treatment plan deposit payments now properly update the plan

================================================================================
PROBLEM
================================================================================
When cashier processed deposit payment:
- Treatment plan didn't update
- Deposit still showed as unpaid
- Plan status remained unchanged
- Treatment couldn't commence

================================================================================
ROOT CAUSE
================================================================================
The casherPayBill function wasn't checking if DENTAL payments were for
treatment plans (deposits, phases, or installments).

================================================================================
SOLUTION
================================================================================
Enhanced casherPayBill function to detect and handle 3 payment types:

1. DEPOSIT PAYMENTS
   - Detects: [PLAN-ID:xxx] in bill description
   - Updates: deposit_paid = TRUE, status = 'accepted'
   - Records: Payment in dental_treatment_payments table
   
2. PHASE PAYMENTS
   - Detects: [PHASE-ID:xxx] in bill description
   - Updates: phase status = 'ready', payment_status = 'paid'
   - Records: Payment with phase_id link
   
3. INSTALLMENT PAYMENTS
   - Detects: "Installment X/Y" + [PLAN-ID:xxx]
   - Updates: Payment schedule status = 'paid'
   - Records: Payment with installment note

================================================================================
HOW IT WORKS
================================================================================

DEPOSIT PAYMENT FLOW:
1. Patient accepts plan → Deposit bill generated
2. Bill description: "Treatment Plan Deposit - Plan Name [PLAN-ID:TP-xxx]"
3. Cashier processes payment
4. Backend detects [PLAN-ID:xxx] pattern
5. Updates treatment plan:
   - deposit_paid = TRUE
   - status = 'accepted'
   - total_paid += amount
   - balance_due -= amount
6. Records payment in history
7. Treatment can now commence!

INSTALLMENT PAYMENT FLOW:
1. Generate installment bill
2. Bill description: "Installment 1/6 - Plan Name [PLAN-ID:TP-xxx]"
3. Cashier processes payment
4. Backend detects installment pattern
5. Updates payment schedule
6. Updates plan totals
7. Records payment

PHASE PAYMENT FLOW:
1. Generate phase bill (to be implemented in frontend)
2. Bill description: "Phase 1 - Phase Name [PHASE-ID:123]"
3. Cashier processes payment
4. Backend detects phase pattern
5. Updates phase status to 'ready'
6. Updates plan totals
7. Dentist can begin phase

DATABASE UPDATES
================================================================================

dental_treatment_plans:
- deposit_paid → TRUE
- deposit_transaction_id → Transaction ID
- status → 'accepted' (from 'pending_acceptance')
- total_paid → Increases with each payment
- balance_due → Decreases with each payment

dental_treatment_plan_phases:
- payment_status → 'paid'
- bill_transaction_id → Transaction ID
- amount_paid → Increases
- status → 'ready' (can begin treatment)

dental_treatment_payment_schedule:
- status → 'paid'
- paid_date → Payment timestamp
- transaction_id → Transaction ID
- payment_method → Cash/Card/Bank

dental_treatment_payments:
- New record for each payment
- Complete payment history
- Links to plan_id and phase_id
